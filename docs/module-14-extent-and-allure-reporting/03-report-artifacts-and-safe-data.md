# Report Artifacts And Safe Data

## Mental Model

Reports are artifacts. They are files created by a test run and kept after the
run completes. Artifacts are useful because they let someone debug a failure
without rerunning the test immediately.

Artifacts can also leak data if the framework is careless. Module 14 treats
safe reporting as part of framework design.

## Artifact Map

| Artifact | Path | Produced by | Purpose |
| --- | --- | --- | --- |
| Extent HTML | `target/extent-report/extent.html` | `ExtentReportManager` | standalone human-readable report |
| Allure raw results | `target/allure-results/` | Allure TestNG integration | structured JSON files and attachments |
| Allure HTML report | `target/allure-report/` | `mvn allure:report` | generated Allure dashboard |
| Log file | `target/logs/test-execution.log` | Log4j2 | chronological execution details |
| Failure screenshots | `target/screenshots/` | `ScreenshotUtils` | visual evidence on failed tests |

## Code Walkthrough

Sensitive data protection is currently visible in:

[src/test/java/com/learning/tests/models/LoginScenario.java](../../src/test/java/com/learning/tests/models/LoginScenario.java)

The record still stores the real password so tests can use it:

```java
String password
```

But `toString()` returns:

```java
password=****
```

This matters because reporting tools often call `toString()` on DataProvider
parameters.

## Framework Nuances

It is not enough to avoid explicit logging of passwords. Frameworks also need
to consider implicit output:

- DataProvider parameter display.
- assertion messages.
- screenshot content.
- browser URL query strings.
- report labels and step names.
- exception messages.

Module 14 checks generated artifacts for `secret_sauce` after the suite run.
That is a practical habit for reporting modules.

## TestNG Default Reports vs Extent vs Allure

| Tool | Strength | Limitation |
| --- | --- | --- |
| TestNG default output | available automatically | basic and not stakeholder-friendly |
| Extent | single readable HTML file | framework owns more setup code |
| Allure | rich labels, steps, attachments, CI-friendly results | requires result generation plus report generation |

## Common Mistakes

- Treating `target/` files as harmless because they are not committed.
- Using raw credentials in scenario names.
- Forgetting reports can be uploaded by CI later.
- Adding every possible artifact and making reports noisy.
- Assuming screenshots cannot contain secrets.

## Interview Readiness

Strong answer:

"A reporting framework should generate useful artifacts but must avoid leaking
sensitive data. I check not only explicit logs but also implicit places such as
DataProvider parameter rendering. In this project the login scenario keeps the
real password for execution but masks it in `toString()` so report tools show
safe output."
